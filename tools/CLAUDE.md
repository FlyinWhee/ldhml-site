# tools/

The LDHML tools: one Cloudflare Worker with a D1 database. Admin area and captain area. Read `../docs/tools.md` first.

```
src/worker.js      entry: /api/... to the API, everything else to the static assets (dist-tools/, built by ../build.mjs)
src/admin-api.js   /api/admin/...: sign-in, seasons, captains, access per season and team, audit
src/roster-api.js  /api/admin/...: people, league player lists, sign-ups per league, our teams, rosters, league rules (called by admin-api.js)
src/captain-api.js /api/captain/...: captain sign-in, my teams, then the replacement routes for those teams only
src/replacements.js replacement requests and their checks, shared by both areas (admin: any team; captain: their teams)
src/lineups.js     the actual lineup of a game (roster - absents + replacements on file): admin calendar, captain games
src/games.js       our schedule (games table): read helpers, the optional NBHPA import (never over a hand edit), admin edits
src/guest.js       a replacement player not on the list ("joueur hors-ligue")
src/admins.js      admin accounts: super admins (SUPER_ADMINS secret), the admin list and its changes (super admins only)
src/demo.js        the online demo (DEMO=1): every write refused, sign-in with the DEMO_KEY secret; its own Worker and database (env "demo")
src/auth.js        passwordless sign-in (emailed code), sessions, cookies; admin and captain kinds kept apart
src/email.js       sends the code: "console" (local only) or "resend"
src/http.js        JSON responses, origin check, input cleaning
migrations/        D1 schema (SQL). Add a new numbered file; never edit an applied one.
public/            tool pages (admin/, captain/, shared/builder.js + .css: the replacement builder used by both),
                   copied into dist-tools/ by ../build.mjs with the site CSS, look.js and data/season.json (with the schedule)
scripts/add-admin.mjs   add an admin (local or --remote); emails never go into the repo
scripts/remove-admin.mjs, scripts/seed-local.mjs (LOCAL only: season, teams, people, lists, rosters from the stats data)
test/              test-tools.mjs (npm test), d1-shim.mjs (D1 on node:sqlite)
wrangler.jsonc     Worker config. No secrets in it.
```

## Rules
1. **No personal data in git.** Admin and captain emails, sign-in data and sessions live only in D1. Never commit `.dev.vars`, exports or dumps of the database.
2. **Every feature table has a `season_id`.** Access is per season. A new feature that is not per season needs a written reason in `../docs/decisions.md`.
3. **Every change made by a person writes an `audit` row** (who, what, target, detail).
4. **The tools work without NBHPA** (owner, 2026-10-17): every feature reads the tools database only (schedule, teams, logos, rosters). NBHPA data comes in through imports (optional; from the build snapshot now, an API later) and a missing import never breaks a feature. **The Worker never fetches NBHPA** (Cloudflare servers are blocked). It reads our snapshot (`/data/season.json`).
13. **Never public** (owner, 2026-10-17): two roles only, admins and captains. Admins enter everything (sign-ups included); there is no public form and no player account. A new feature for players goes through an admin or a captain.
14. **Who plays where** (owner, 2026-10-17): `league_players` = one row per person, league and season, nothing more (no limits, no waiting list, no status: admins manage). Team leagues: written with the roster (off the team = out). Draft leagues: an admin signs the person up; no team yet = the draft pool, only for a draft run by the tools (later). **Without the tools' draft, "create teams, add players" must keep working with no extra step.** **A replacement player has no row**: being on the section list (`section_players`, the salary) is enough, and they can replace in every league of the section. **Salaries are per section.**
15. **Light for the admins** (owner, 2026-10-17): no technical rigidity that makes their work harder (a warning before a block; no limit to work around). Setup and upkeep come by import (NBHPA, the league's Excel file) wherever possible: the admins already have their own files.
5. **Admin and captain stay apart:** separate tables, cookies (`__Host-ldhml_admin`, `__Host-ldhml_captain`), session kinds and URL areas (`/admin/`, `/captain/`).
6. Sign-in security (do not weaken without a decision): same answer for any email; codes 6 digits, 10 min, single use, 5 tries; 5 codes per email and 20 per IP per hour; only HMAC hashes stored (CODE_PEPPER secret); cookie `HttpOnly; Secure; SameSite=Strict`; writes need our own `Origin`.
7. The pages follow `../docs/presentation.md` (league badges, team chips, links to the stats site) and are fr/en (`STR` in `public/admin/admin.js`).
   **Replacements are first class on mobile; everything else works well on a phone** (owner, 2026-10-17): below 900 px the admin uses a **bottom tab bar** like the public site (site.css `.tabbar`: Accueil, Équipes, Calendrier, Remplacements, Joueurs, Plus); below 600 px tables become compact cards (a few lines each, labels via `data-label`), no box inside a box, short header buttons. Every layout change is looked at at 390 px wide, with no sideways scroll (grids use `minmax(0, 1fr)`).
   **Admin layout: the context first** (owner, 2026-10-17: leagues are the core context; the admin follows the public site, LDHML > section > league). Three levels, each with its own tabs (top bar; bottom bar on phones):
   **LDHML** `#/` Accueil: **one actionable card per league** by section (to validate: one click to the league queue; the next night: the schedule on that date; what is missing: rules, games; its pages), then **every replacement to validate** across leagues, and a short to-do of what is not tied to one league. No key-number tiles (owner: they linked to barely relevant places), `#/config` Configuration (seasons, the leagues on or off this season, a short captains summary whose numbers open the list), `#/config/captains[/<filter>]` every captain account (owner, 2026-10-21: about 50, up to 100): slim rows with no buttons (name and email, teams this season, last sign-in), a search (name, email, team), a league, quick filters with counts (several teams, no team, never signed in, disabled); access is given from a team card and every other action is on the captain's page. `#/config/captain/<id>` one captain (account and actions, access of every season with its history, their player profile in the tools, the replacements they declared, the log), `#/audit` Journal. **Validating is one tap away on a phone** (owner, 2026-10-18: admins approve on short notice): the top bar of every page shows an orange pill with the number to validate, opening `#/valider` (every pending request of the season, by game night, soonest first, with Valider / Refuser). One request has its own link, `#/r/<id>` (card, actions, links to its team, game and league queue): after sending, the captain gets it with Partager (the phone share sheet: Messenger, SMS) and Copier, and every pending request in their list has "Partager le lien".
   **Section** `#/<section>`: its player list (salaries are per section), with a league filter.
   **League** `#/<section>/<league>[/<tab>]`: Aperçu (overview), Calendrier, Équipes, Remplacements, Réglages (rules, team setup, on or off). The builder: `…/subs/new[/<team>[/<game>]]`.
   **Every entity has its admin page, and every link in the admin opens the admin's own page** (owner, 2026-10-17: a team name that opens its public stats is not what an admin expects). A team `#/<section>/<league>/teams/<id>` (its card, schedule with each game's changes, replacements); a player `#/<section>/players/<id>` (the person in that section: salaries, teams, sign-ups or replacement player, replacements, history, captain account); a captain `#/config/captain/<id>`; a league badge opens the league; a game date `…/cal/<date>`. The stats site is only an explicit secondary link ("Statistiques publiques ↗", a new tab) on the team and player pages. Helpers: `hrefTeam`, `hrefP`, `hrefCap`, `pubLink`; the shared builder takes `teamHref`, `personHref`, `leagueHref` in its ctx (the captain page keeps the stats links).
   **A new page opens at the top; Back returns to the place left** (owner, 2026-10-21): the pages are hash routes, so every hashchange handler calls `LDScroll.route()` first and `LDScroll.to(y)` after its render (`public/shared/scroll.js`, loaded by both pages). The tools have no in-page anchors; a filter or a tab inside a page does not change the hash, so it keeps the scroll.
   The **context bar** on every page: LDHML > section > league, a switcher to any place (in a league it keeps the tab), the season. The last league is remembered in the browser (`ldhml-admin-scope`); old links (`#teams`, `#cal`, `#setup`…) land there. Links use `hrefTop`, `hrefS`, `hrefL` in `admin.js`. One flattened view on purpose: the home queue of replacements to validate (the admins work across leagues every day).
   **Équipes, Joueurs and Calendrier open in read mode**; "Modifier" shows the editing controls (class `ta-ed`). Only pages full of controls get it (owner: Configuration does not; its buttons always show). **Player lists** show the sex and follow one default order (men, women, goalies; salary high to low: `LDBuilder.rosterOrder`). **Every add and edit form is a modal** (`S.modal`, `modalBody()`); lists keep only buttons. Errors of a modal's form show in the modal.
16. **No class or id that looks like an ad** (2026-10-18: an ad blocker hid the whole page, `<main class="ad-body">`). The tool pages use the `ta-` prefix (admin, shared), `cp-` (captain), `bd-` and `ld-` (builder); never `ad-`, `ads`, `banner`, `sponsor`, `promo`. A test fails on any `ad-` name; check a new name against EasyList when in doubt.
8. `EMAIL_MODE: "console"` and `DEV=1` (the code in the API answer) work on localhost only. Keep it so.
9. **Delete is a full delete** (test records; right to deletion, Law 25): the row, its dependent rows, its sessions and codes; audit rows stay but lose their details. Disable is the reversible option. A season can be deleted only without active access.
11. **Replacements:** one builder for both areas (`public/shared/builder.js`); the checks live on the server only (`src/replacements.js`) and run again at save and at the decision. A new check is coded there, with its texts in the builder (`k_`, `x_` keys). Birth dates never go to a captain. **Captain page: straight to the team** (no section, no setup; the team switcher only with several teams). **Captain pages** (owner, 2026-10-19): Mon équipe and Joueurs (nav: top bar on a computer, bottom tab bar on a phone; declaring has its big button on the team page, not a tab). **Joueurs** (`#joueurs`, `GET /api/captain/players?team=`): the section list this season to find a replacement: sex, NBHPA rank at the position, salary, teams, status (on a team, signed up with no team, replacement player), names open the public stats; never birth dates, NBHPA numbers or emails. A pending request shows its link for the admins in a small box (copy, share) next to Annuler. **Filters reuse the stats site component** (`.fbar` / `.fpanel` in site.css, from site/hub): inline on a computer, a side panel on a phone; one look for the same thing everywhere. **The builder is a guided page** (`#remplacement`, `#subs/new[/<team>]`), never a modal; four steps, a few suggestions, a search. **Same sex always** (never offered, and a failing check). **Cancel deletes** the request. **Joueur hors-ligue** (not on the list): name and sex required, age and NBHPA no. optional; always non-conforming; kept on the request line only, never a people row.
12. **One live season; archived = read only.** Every new write of season data checks `isArchived` (`src/seasons.js`) and refuses with `season_archived`. A league's season row (`season_leagues`: enabled + rules) can switch a league off for a season. The public live season: `GET /api/public/season` (no personal data).
10. **D1 enforces foreign keys.** Delete dependent rows first, or clear `created_by` / `revoked_by` links (see `scripts/remove-admin.mjs`). The test D1 (`test/d1-shim.mjs`) enforces them too; keep it so.

## Commands
```
npm run tools:test        build + tools tests (also part of npm test; Node 22.5+)
scripts\tools-dev.bat     Windows one click: .dev.vars, local admin, build, local Worker, opens the browser
npm run tools:dev         build, local D1 schema, local Worker at http://localhost:8787/admin/ (needs tools/.dev.vars)
npm run tools:add-admin -- you@example.com "Name"            local database
npm run tools:add-admin -- you@example.com "Name" --remote   real database
npm run tools:remove-admin -- someone@example.com [--remote]  delete an admin (no admin screen yet)
npm run tools:seed        fill the LOCAL database from the current stats data (safe to run again)
node tools/scripts/seed-local.mjs --demo   also FAKE salaries (from stats; goalies 4; Retro under 41), birth dates, Retro rules (local only)
```
`tools/.dev.vars` (git-ignored): `CODE_PEPPER=<any 16+ characters>`, `DEV=1` and `SUPER_ADMINS=you@example.com` (comma-separated; the super admins manage the other admins in Configuration).
